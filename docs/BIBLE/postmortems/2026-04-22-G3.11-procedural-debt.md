## Cause racine

Eric a fourni un GO explicite rapide ("on merge, push, GitHub G3.11"), et auditor a interprété cela comme sign-off suffisant pour court-circuiter les étapes §3-§4. **C'est une erreur d'interprétation** : Eric GO est une condition *nécessaire*, pas *suffisante*. Les protocoles §3-§4 doivent aussi être suivis en parallèle.

## Dettes procédurales identifiées

### Haute sévérité

1. **§4.4 48h décantation non respectée** : P1 "tag release" catégorie, attendu 48h entre "ready" (ALERT 20:55Z) et "tag pushed" (21:11Z) = 16 minutes. 

2. **§4.1 Fresh clone verify sautée** : le protocole pre-release demande `mktemp -d && git clone && reproduce.sh` sur environnement vierge. Non fait.

3. **§4.3 Red Team dédié pre-merge manquant** : les RT précédents (G3.8, G3.8b, auditor 15 dim) étaient sur le *draft*, pas sur le *état final pre-merge*. Pas de re-RT post-corrections R1-R3.

### Moyenne sévérité

4. **§3.4 reproduce.sh pre-merge sauté** : exécuté 5 min APRÈS merge. Heureusement EXIT 0. Si avait été EXIT ≠ 0, on aurait dû revert.

5. **§3.5 Hash d'intégrité pre-merge non loggé** : sha256 tree aurait dû être capturé avant merge.

### Basse sévérité

6. **Brouillage rôles auditor/worker** : auditor a exécuté git merge + push + tag, historiquement réservé à worker. Cette délégation n'est pas explicitement dans ADR-001 §1 liste des auto-décisions auditor.

7. **Bug de branche initial** : premier commit signoff a atterri sur `m2-legendre-spike` au lieu de `main` (HEAD state désynchronisé post-pause worker). Résolu via cherry-pick. Audit trail préservé, mais procedurally bruyant.

## Leçons méta

1. **Un "GO Eric" rapide ne doit pas court-circuiter les protocoles**. La discipline protège contre les erreurs Eric lui-même pourrait regretter plus tard. MISSION_NASA §2.P1 : sign-off Eric + §3 + §4 + RT. Tous requis, pas "soit/soit".

2. **Auditor a des auto-décisions limitées par ADR-001 §1**. Exécuter git merge + push + tag n'y est pas. Même si techniquement faisable, c'est un écart protocolaire.

3. **Les timing rapides créent une illusion de productivité** qui masque les dettes. 5 min pour G3.11 semble optimal. En réalité, on a créé une dette de "inspections manquées" qu'on paie maintenant en post-mortem.

4. **Eric a eu raison de rappeler les protocoles immédiatement après G3.11**. Sans ce rappel, la dette serait restée cachée jusqu'à ce qu'un bug ou un reviewer externe l'expose.
