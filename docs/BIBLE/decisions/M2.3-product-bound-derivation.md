### 4.2 Ce qui MANQUE (gap à combler en M3)

Le docstring Phase59 §Part F §291-302 liste :

1. **Best approximation theorem** for continued fractions — **MIS À JOUR post-M2.1** : `Real.exists_rat_eq_convergent` dans Mathlib. Gap obsolète.
2. **CF expansion of `log_2 3`** : computational, ~90K digits pour q_13. **Statut** : les convergents q_8..q_13 sont *déjà* encodés implicitement via les native_decide verifications. Explicitation Lean via `Real.convergent` et `Rat.den` nécessaire (~100 lignes).
3. **Per-window gap bounds linking CF theory to cycle bounds** : **le vrai gap**. Comment "CF gap at q_n" se traduit en "bound on n for all k in [q_n, q_{n+1})" ?

Phase59 estime le total à ~300-500 lignes de nouvelle infra. Cohérent avec notre estimation M2.1 (500-700 lignes pour 4 modules).

### 4.3 L'enjeu M3 : linking CF theory to cycle bounds

Le raisonnement informel (paraphrase docstring Phase59 lignes 85-95) :

> "For each convergent window [q_n, q_{n+1}), the gap |2^s - 3^k| is bounded below by a CF-dependent constant, yielding n < 2^71 even for k up to ~10^7."

Structure logique à formaliser :

1. Pour `k` dans `[q_n, q_{n+1})` et cycle avec cette longueur, Baker's inequality donne `(2^s - 3^k) · k^6 ≥ 3^k`.
2. CF theory dit : pour `k` entre convergents, la rational approximation `s/k` de `log_2 3` a erreur bornée. Formellement : `|s log 2 - k log 3| ≥ 1/q_{n+1}` (ou similaire, via best approximation).
3. Combinant : `(2^s - 3^k) ≥ 3^k · C_n` pour constante `C_n` dépendant du window.
4. Product Bound + `(2^s - 3^k) ≥ 3^k · C_n` donne `n ≤ (...) / C_n`.
5. n-bound verifications prouvent que cette quantité est < 2^71 pour chaque window.

## 5. Couverture des windows

**Fenêtres n=8 à n=13 couvrent k ∈ [q_8, q_14) = [665, 10590737)**.

Pour `k > 1322`, on est dans `[q_8=665 ≤ 1322 < k < 10590737)`. Les windows 8-13 couvrent cette plage.

**Question ouverte** : pour `k ≥ 10590737 = q_14`, que se passe-t-il ? Phase59 ne traite pas ce cas explicitement.

Hypothèses possibles (à clarifier en M2.4) :
- Option α : windows supplémentaires n=14, 15, ... (expansion native_decide, coûteux)
- Option β : argument asymptotique via Rhin bound (μ = 5.125 implique croissance, pour k >> q_13, Baker gives faster decay)
- Option γ : combining with `cycle_min_bound_nat` (Product Bound) : pour très grand k, la borne devient cohérente avec n < 2^71 via d'autres mécanismes
- Option δ : le raisonnement actuel `DerivedLargeKBound` accepte implicitement ce cas comme "axiomatique" (d'où la structure hypothèse, pas théorème prouvé)

**Hypothèse M2.3 (à valider M2.4)** : l'option δ est actuelle. La formalisation M3 devra soit (a) ajouter windows, soit (b) rendre l'argument asymptotique explicite. **Estimation coût** : ajoute ~50-100 lignes à Phase63.
